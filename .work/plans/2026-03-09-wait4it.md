# Wait4It — Pop Up Video-Style Commentary Sharing

> A static site where users paste a YouTube link, add timestamped commentary while watching, and generate a shareable URL that plays the video with Pop Up Video-style speech bubbles appearing at each timestamp — spoiler-free, no login, no backend.

## Tasks

- [ ] **Set up project scaffolding** — Create `index.html` with base structure, inline CSS/JS, and a minimal dev setup (e.g. live-reload via `npx serve` or similar). No build tools.
  - **Done when:** A single `index.html` opens in a browser and shows a styled landing state with a URL input field.

- [ ] **Implement YouTube URL parsing** — Accept various YouTube URL formats (watch, short, embed) and extract the video ID. Validate input and show error for invalid URLs.
  - **Done when:** Pasting any common YouTube URL format extracts the correct video ID; invalid URLs show an inline error.

- [ ] **Embed YouTube player with IFrame API** — After a valid video ID is extracted, embed the video using the YouTube IFrame Player API following the project's YouTube Embed convention (nocookie, sandboxed, `enablejsapi: 1`, overlay strategy).
  - **Done when:** Video loads and plays in the embedded player with IFrame API state events firing correctly.

- [ ] **Build creator mode: capture timestamped comments** — Add a "Pop!" button that auto-pauses the video, captures `getCurrentTime()`, and opens a text input. User types their comment and confirms. Store comments in an in-memory array sorted by timestamp. Show a running list of added comments below the player with edit/delete controls.
  - **Done when:** User can pause, add a comment at the current timestamp, see it in the list, edit it, and delete it. Multiple comments (including same-timestamp) work correctly.

- [ ] **Add localStorage draft persistence** — Auto-save the current video ID + comments array to localStorage on every change. On page load (with no hash data), restore the draft if one exists. Add a "Clear draft" button.
  - **Done when:** Closing and reopening the tab restores the in-progress commentary. Clear draft removes it.

- [ ] **Implement URL hash encoding** — Serialize the commentary data (video ID + array of `{time, text}`) as JSON, compress with LZ-String, and encode into the URL hash fragment. Add a "Generate Link" button that builds and copies the shareable URL.
  - **Done when:** Clicking "Generate Link" produces a URL like `site.com/#compressed-data`, copies it to clipboard, and shows confirmation. URL length is displayed with a warning if approaching ~8KB.

- [ ] **Build viewer mode: decode hash and render** — On page load, detect a hash fragment, decode and decompress it, extract video ID and comments. Embed the video and switch to viewer layout (no creator controls).
  - **Done when:** Opening a generated link loads the video and prepares comments for display. Creator UI is hidden.

- [ ] **Implement Pop Up Video bubble display** — During playback, poll `getCurrentTime()` on an interval (~250ms). When a comment's timestamp is reached, show it as a speech-bubble overlay on/near the video with a pop-in animation. Bubble auto-dismisses after a few seconds (scaled to text length). Track which comments have already been shown to avoid repeats on normal playback; re-show on seek-back.
  - **Done when:** Comments pop up as animated speech bubbles at the correct timestamps, auto-dismiss, and re-trigger correctly on seek.

- [ ] **Style and polish** — Design the speech bubble to evoke VH1 Pop Up Video (rounded bubble, pointer/tail, bold text, pop-in animation). Style the creator and viewer layouts to be clean and mobile-friendly. Add a brief "how it works" blurb on the landing page.
  - **Done when:** The app looks polished on desktop and mobile, bubbles feel like Pop Up Video, and a first-time user understands the flow without instructions.

- [ ] **Handle edge cases and limits** — Gracefully handle: invalid/expired hash data, URL too long (offer fallback or warning), video unavailable, mobile IFrame API quirks, rapid consecutive comments at close timestamps (stagger bubbles).
  - **Done when:** All identified edge cases degrade gracefully with user-facing messages where appropriate.
